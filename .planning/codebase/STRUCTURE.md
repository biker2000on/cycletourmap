## Directory Purposes

**`src/components/`:**
- Purpose: Reusable Vue single-file components shared across routes
- Contains: Layout components (Nav, Auth), feature components (Leaflet, Popups, Tabulator), utility components (Buttons, Toggle)
- Key files:
  - `Leaflet.vue` - Interactive map visualization
  - `Home.vue` - Landing page
  - `Auth.vue`, `AuthStrava.vue` - Authentication flows
  - `Rides.vue`, `Strava.vue`, `StravaData.vue` - Strava data display
  - `Profile.vue`, `ProfileNav.vue` - User profile management

**`src/views/`:**
- Purpose: Route-level page components (loaded via Vue Router)
- Contains: Full-page views for each route
- Key files:
  - `Home.vue` - Landing page view
  - `About.vue` - About page view

**`src/router/`:**
- Purpose: Vue Router configuration and route definitions
- Contains: Route paths, lazy-loaded components, navigation setup
- Key files:
  - `index.js` - Route definitions with lazy loading
  - `router.js` - Router history configuration

**`src/store/`:**
- Purpose: Centralized state management with Vuex
- Contains: Store state, mutations, actions, modules (currently mostly empty)
- Key files:
  - `index.js` - Vuex store creation and configuration

**`src/graphql/`:**
- Purpose: Auto-generated GraphQL operation strings
- Contains: Query and mutation definitions for Apollo Client
- Key files:
  - `queries.js` - GraphQL queries (getTour, listTours, getActivity, listActivities, getAthlete, getAuth)
  - `mutations.js` - GraphQL mutations (createTour, updateTour, deleteTour, createActivity, deleteActivity, createAthlete, deleteAthlete, createAuth, deleteAuth)
  - `subscriptions.js` - GraphQL subscription operations (if any)
- Note: Auto-generated by `postgraphile` or code generation tool - do not edit manually

**`src/plugins/`:**
- Purpose: Vue plugin integrations and configurations
- Contains: Third-party service initialization
- Key files:
  - `apollo.js` - Apollo Client configuration with multiple auth strategies (Cognito, API Key, IAM - legacy)
  - `vuetify.js` - Vuetify Material Design framework setup
  - `analytics.js` - Vue3-Analytics integration
  - `amplify.js` - AWS Amplify integration (legacy)
  - `webfontloader.js` - Web font loading

**`src/utilities/`:**
- Purpose: Shared helper constants and utility functions
- Contains: Constants for field names, helper functions
- Key files:
  - `activityKeys.js` - Array of Strava activity field names (50+ fields)
  - `athleteKeys.js` - Array of athlete profile field names

**`src/styles/`:**
- Purpose: Global SCSS stylesheets
- Contains: CSS variables, mixins, global styles
- Applied to: All components via Vuetify and custom CSS

**`src/assets/`:**
- Purpose: Static frontend assets
- Contains: Images, logos
- Key files:
  - `logo.png`, `logo.svg` - Application branding

**`backend/migrations/`:**
- Purpose: Version-controlled PostgreSQL schema
- Contains: SQL migration files applied in order (001-006)
- Key files:
  - `001-create-tables.sql` - Creates users, Activity, Athlete, Auth, Tour, TourActivities tables
  - `002-user-functions.sql` - Database functions for user management
  - `003-update-current-user-id.sql` - User ID context updates
  - `004-add-rls.sql` - Row-level security policies
  - `005-fk-index.sql` - Foreign key indexes
  - `006-cols-update.sql` - Column updates and refinements

**`public/`:**
- Purpose: Static files served directly by web server
- Contains: Images, GIFs, public resources
- Key folders:
  - `images/` - Component and page images
  - `strava/` - Strava integration assets
  - `gifs/` - Animated GIFs for tutorials/documentation

**`amplify/`:**
- Purpose: AWS Amplify backend configuration (deprecated/legacy)
- Contains: Amplify CLI configuration, Lambda functions, AppSync GraphQL
- Status: Appears to be removed based on recent commit history but directory remains

## Naming Conventions

**Files:**
- Vue components: PascalCase.vue (e.g., `Leaflet.vue`, `AuthStrava.vue`)
- Utilities: camelCase.js (e.g., `activityKeys.js`, `athleteKeys.js`)
- GraphQL operations: snake_case or camelCase.js (e.g., `queries.js`, `mutations.js`)
- Database migrations: `NNN-descriptive-name.sql` (e.g., `001-create-tables.sql`)

**Directories:**
- lowercase for feature areas: `components/`, `views/`, `router/`, `store/`, `plugins/`, `utilities/`, `graphql/`
- PascalCase for backend: `Activity`, `Athlete`, `Auth`, `Tour` (table names in migrations)

**Component Props/Data:**
- camelCase for data properties and methods
- PascalCase for component names
- snake_case for GraphQL field names (matching Strava API and database column names)

## Where to Add New Code

**New Feature (Maps, Rides Management, Tours):**
- Primary code: `src/components/[FeatureName].vue` (presentation) + new queries in `src/graphql/queries.js`
- State: Add to `src/store/index.js` modules if complex, else use Apollo cache
- Styling: Scoped styles in component or `src/styles/[feature].scss`
- Database: Add migration file to `backend/migrations/` with next sequential number

**New Component/Module:**
- Implementation: `src/components/[ComponentName].vue` for reusable, or `src/views/[PageName].vue` for route-level
- Route: Add entry to `src/router/index.js`
- Props: Define in component's `<script>` block

**Utilities:**
- Shared helpers: `src/utilities/[utilityName].js`
- Constants: Add to existing utility file or create new one
- Export as named exports: `export const helperName = ...`

**Database Queries:**
- Modify GraphQL operations: `src/graphql/queries.js`, `src/graphql/mutations.js`
- Note: These are auto-generated from PostGraphile schema
- To change queries: Either regenerate from PostGraphile or edit manually with caution

**Styling:**
- Global styles: `src/styles/global.scss`
- Component styles: Use `<style scoped>` in .vue files
- Vuetify overrides: Modify Vuetify config in `src/plugins/vuetify.js`

**Database Schema Changes:**
- Create new migration: `backend/migrations/NNN-description.sql`
- Use next sequential number (007, 008, etc.)
- Apply with PostgreSQL client or migration tool
- Include comments explaining changes
